## [C-Kermit's First Release in 15 Years Marks Kermit Protocol's 45th Anniversary](https://changelog.complete.org/archives/44456-celebrating-45-years-of-kermit-with-the-first-new-c-kermit-release-in-15-years-and-working-with-a-decades-old-c-codebase) ⭐️ 7.0/10

A new release of C-Kermit has been published, the first in 15 years, coinciding with the 45th anniversary of the Kermit file-transfer protocol originally developed at Columbia University in 1981. The release revives a piece of computing history still actively used in embedded development and serial communications, and highlights the challenges of maintaining a decades-old, extraordinarily portable C codebase. The post discusses working with C-Kermit's legendary codebase, famously riddled with #ifdefs to support countless Unix variants, VMS, and other legacy platforms — arguably more portable than Unix itself.

hackernews · roryirvine · Aug 3, 17:02 · [Discussion](https://news.ycombinator.com/item?id=49158474)

**Background**: Kermit is a file transfer and terminal communications protocol developed at Columbia University in 1981 by Frank da Cruz and Bill Catchings to move files reliably over serial connections between wildly different computers. C-Kermit is the portable C implementation that runs on Unix, VMS, and many other systems. Though largely superseded by modern protocols like SFTP, it remains popular for embedded development and serial console automation.

## [Jane Street Open-Sources Bonsai, Its OCaml Web UI Framework](https://github.com/janestreet/bonsai) ⭐️ 7.0/10

Jane Street has open-sourced Bonsai, an OCaml library for building performant, reactive web applications, partly inspired by Elm and used internally to build nearly all of the firm's web apps. It gives the OCaml community a battle-tested, production-scale UI framework and enables sharing types and code between frontend and backend in a single strongly-typed functional language. Bonsai builds on Jane Street's Incremental library and Incr_dom for efficient reactive DOM updates, though early adopters note broken doc links and questions about whether it forgoes the JS/React ecosystem.

hackernews · KolmogorovComp · Aug 3, 08:29 · [Discussion](https://news.ycombinator.com/item?id=49152842)

**Background**: OCaml is a statically-typed functional language heavily used at Jane Street for trading systems. Bonsai compiles to JavaScript via js_of_ocaml, competing with alternatives like Melange (used by Ahrefs) which lets OCaml interop more directly with the React/JS ecosystem. Incr_dom, Bonsai's predecessor, provides Elm-like architecture with incremental computation for efficient re-rendering.

## [ML reviewer calls for desk-rejecting papers without reproducible code](https://www.reddit.com/r/MachineLearning/comments/1vei12v/its_time_to_desk_reject_papers_that_dont_include/) ⭐️ 7.0/10

A Reddit post by an ML conference reviewer argues that top venues like NeurIPS should desk-reject submissions that don't include runnable code, reporting that of 12 papers they reviewed this year, only 1 shipped a fully runnable training-to-evaluation pipeline while 7 provided no code at all. The claim highlights the ongoing reproducibility crisis in machine learning and pressures conferences to strengthen code-submission requirements, which would affect thousands of authors and the credibility of published results. The reviewer notes that 3 of the 5 papers providing any code contained obvious bugs that invalidated the results, and argues the core problem is misaligned incentives: hiding code carries no penalty while releasing it only increases rejection risk.

reddit · r/MachineLearning · /u/Flaky-Ambition5900 · Aug 3, 16:17

**Background**: NeurIPS already requires authors to fill out a Paper Checklist covering reproducibility, ethics, and experimental rigor, but code release remains encouraged rather than strictly enforced. Reviewers typically evaluate submissions on methodology and reported metrics like AUROC without running the actual code, so bugs and cherry-picked results can go undetected. 'Desk reject' means an editor or program chair rejects a paper before peer review even begins based on formal criteria.
