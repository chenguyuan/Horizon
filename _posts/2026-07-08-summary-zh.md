## [欧盟强制要求 2026 年 7 月起所有新车配备驾驶员监控摄像头](https://allaboutcookies.org/eu-mandatory-distracted-driver-system) ⭐️ 7.0/10

根据欧盟《一般安全条例》（GSR），从 2026 年 7 月起，所有在欧盟销售的新登记乘用车、面包车、卡车和客车都必须配备高级驾驶员分心警告系统（ADDW），通常是基于摄像头的驾驶员监控系统（DMS）。该技术会跟踪视线方向、头部动作、眨眼频率和注意力水平，以提醒疲劳或分心的驾驶员。 这一强制规定预计将影响约 1800 万辆欧洲汽车，重塑每位新车买家的座舱体验，同时也引发了关于监控、数据隐私和驾驶员自主权的重大担忧。它还标志着监管层面对消费品中始终在线的生物识别监控的更广泛推动，可能会扩展到其他司法管辖区和设备类别。 该系统称为 ADDW，是更新版 GSR 最后阶段的一部分，使用 AI 驱动的神经网络实时分析眼球运动、眨眼速度和视线方向；Mobileye 和 Smart Eye 等供应商已将其与 ADAS 摄像头融合以获取道路上下文。驾驶员监控并非新事物——丰田早在 2006 年就推出了首个 DMS——但这是首个覆盖所有车辆类别的全面强制规定。

hackernews · nickslaughter02 · 7月7日 20:50 · [社区讨论](https://news.ycombinator.com/item?id=48823557)

**背景**: 欧盟《一般安全条例》（GSR）是一个全面的车辆安全框架，自 2022 年起分阶段实施，要求新车配备智能速度辅助、紧急车道保持和事件数据记录仪等功能。驾驶员监控系统（DMS）使用对准驾驶员面部的红外或可见光摄像头，通过计算机视觉推断注意力状态，通常不会对外记录或传输画面。ADDW 要求专门针对分心驾驶（不同于早期专注于疲劳的 DDAW 规定），继早期新车型认证分阶段实施后，从 2026 年 7 月起适用于所有新登记车辆。

## [微软据报解散 id Software 旗下 idTech 引擎团队](https://gamefromscratch.com/microsoft-fire-idtech-team-at-id-software/) ⭐️ 7.0/10

据报道，微软在《毁灭战士：黑暗时代》DLC 发布同一天解散了 id Software 的 idTech 引擎团队，实际上终结了这一有着 30 年历史的自研引擎的内部开发。此举意味着 id Software 未来的作品可能会转向 Unreal Engine 5 或其他第三方引擎。 idTech 是游戏史上最具历史意义的引擎系列之一，曾通过《毁灭战士》《雷神之锤》和《德军总部》推动 3D 图形技术的发展，其消亡标志着游戏行业围绕 Epic 的 Unreal Engine 加速整合的一个象征性节点。这也反映出大型发行商放弃自研技术、转而使用通用引擎和可替换合同工的更广泛趋势。 此次裁员是微软 2020 年以 75 亿美元收购 id Software 母公司 ZeniMax Media 后大规模游戏业务裁员的一部分，也有评论者指出文章缺乏具体证据来证明哪些程序员被解雇。值得注意的是，与早期的 idTech 不同，idTech 5 及之后的版本从未开源，因此如果团队被彻底解散，代码库可能会被永久封存而不是交给社区。

hackernews · bauc · 7月7日 15:33 · [社区讨论](https://news.ycombinator.com/item?id=48819244)

**背景**: id Software 由 John Carmack 和 John Romero 创立，开创了第一人称射击游戏类型，并开发了一系列相继问世的游戏引擎（idTech 1 至 7），这些引擎被广泛授权给其他工作室并常常开源，影响了 Valve 的 GoldSrc 和 Infinity Ward 的 IW 引擎等衍生产品。微软于 2020 年以 75 亿美元收购贝塞斯达母公司 ZeniMax Media，从而间接收购了 id Software，这是游戏史上最大的交易之一。近年来，idTech 面临 Unreal Engine 日益增长的压力，后者凭借丰富的工具链和庞大的合同工人才库，已成为 AAA 行业主导的授权引擎。

## [sqlite-utils 4.0 发布，新增数据库迁移和嵌套事务功能](https://simonwillison.net/2026/Jul/7/sqlite-utils-4/#atom-everything) ⭐️ 7.0/10

Simon Willison 发布了 sqlite-utils 4.0，这是自 2020 年 11 月 3.0 版本以来的首次主要版本升级，引入了三大重要特性：基于 Python 的数据库模式迁移、通过新增 db.atomic() 方法实现的嵌套事务，以及对复合外键的支持。该版本是项目的第 124 次发布，同时包含一些小但重要的破坏性变更，相关内容已在升级指南中说明。 sqlite-utils 是一个广泛使用的 Python 库和命令行工具，此次将模式迁移作为一等特性加入，填补了之前迫使开发者转而使用 Alembic 或手写脚本的重大空白。嵌套事务和复合外键的加入也让 sqlite-utils 在保持轻量级、专注于 SQLite 的易用性同时，向重量级 ORM 的功能对等迈进了一步。 迁移以带装饰器的 Python 函数形式定义在 migrations.py 文件中，通过 `uvx sqlite-utils migrate data.db migrations.py` 命令应用，底层利用已有的 table.transform() 方法，该方法实现了 SQLite 官方推荐的模式：创建新表、复制数据、删除旧表、重命名。由于 SQLite 原生的 ALTER TABLE 功能非常有限，这种基于 transform 的方法使迁移能够处理列类型变更、重命名等原本不支持的操作。

rss · Simon Willison · 7月7日 19:32

**背景**: sqlite-utils 是由 Simon Willison 创建的 Python 命令行工具和库，用于操作 SQLite 数据库，因能将 JSON、CSV 或 TSV 数据直接导入自动生成的 SQLite 表而广受欢迎。它是更大的 Datasette 生态系统的一部分——一个开源的多功能工具，用于通过交互式网站和 API 探索和发布数据。模式迁移是应用开发中的标准实践，用于对数据库结构进行版本管理并随时间演进，确保变更在各环境中一致地应用。
